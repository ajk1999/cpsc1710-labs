Worksheet 05 · Q1.3

A decision boundary, by hand

≈ 15 minutes

A classifier computes a score = (each feature × its weight, all added up) + bias. A positive score puts a point on one side of the boundary; a negative score puts it on the other. The boundary itself is wherever the score is exactly 0.

Suppose the quadratic model uses features [x1, x2, x1², x1·x2, x2²], weights [0, 0, −1, 0, −1] and bias 0.45. Most of the weights are 0, so the score simplifies to 0.45 − x1² − x2². (Your notebook may use different numbers; you can redo this table with yours.)

Trace
point (x1, x2)x1²x2²score = 0.45 − x1² − x2²+ or −?
A (0.2, 0.1)0.040.010.40+
B (0.9, 0.3)
C (0.0, 0.7)

Now use the linear model, with features [x1, x2], weights [1, 0] and bias 0. What is its score for A, B and C? What shape is its boundary?

Think

The quadratic boundary is where x1² + x2² = 0.45. That is a circle. What is its radius? Which bias would make a circle of radius 0.5?

Why can no straight line separate one ring of points from another ring around it?

Tweak

In your notebook, change BIAS_QUADRATIC. Predict first: does the circle grow or shrink?

Check your numbers

B: 0.81, 0.09, score −0.45, so B is outside the circle. C: 0, 0.49, score −0.04, so C is just barely outside. Linear scores equal x1: 0.2, 0.9 and 0.0 (C sits exactly on the boundary), and the boundary is the straight vertical line x1 = 0. The circle's radius is √0.45 ≈ 0.67; bias 0.25 gives radius 0.5. A larger bias makes a larger circle.

One step of gradient descent

≈ 15 minutes · calculator welcome

The model predicts w × x. The data are x = [1, 2, 3] and y = [2, 4, 6], so the best w is 2. Start at w = 0 with a learning rate of 0.1.

errors   = w * x - y
loss     = mean(errors²)
gradient = 2 * mean(errors * x)
new w    = w - learning_rate * gradient

With a learning rate of 0.25, the new w is 4.67, which is 2.67 away from 2 (it started 2 away). Each step overshoots by more, so w bounces farther away every time.

Worksheet 07 · Part 2

Reading dense textbook code

≈ 15 minutes

Chapter 4 packs a lot into each line. Two habits make it readable: unchain a line into one step per line, and rewrite library calls as plain loops. Practice both here on lines that HW3 does not grade, then use them on the Q2 questions.

Unchain

Early in the chapter, the book compares one image of a 3 with the "average 3":

dist_3_abs = (a_3 - mean3).abs().mean()
dist_3_sqr = ((a_3 - mean3)**2).mean().sqrt()

Pretend each image has only three pixels: a_3 = [0, 0.5, 1] and mean3 = [0.2, 0.5, 0.6]. Fill in one row per step.

Rewrite as a loop

Chapter 4 often uses torch.where(condition, a, b). Item by item, it means "if the condition holds, take a; otherwise take b". Here is a practice line (not from the book) and its plain-Python version:

labels = torch.where(temps > 20, 1, 0)

# plain Python
labels = []
for t in temps:
    if t > 20:
        labels.append(1)
    else:
        labels.append(0)

Now write the plain-Python version of (temps > 20).float().mean(). What does the result tell you about temps?

Using AI beyond "write it for me"

The AI that wrote your code can also help you understand it. Paste your cell and try one of these prompts:

  • Predict with me"Explain this cell line by line for a beginner. After each line, ask me to predict what it does before you tell me."
  • Quiz me"Ask me three short questions about this code. Wait for my answers before giving yours."
  • Show every step"Rewrite this without numpy or sklearn, as plain Python loops, so I can see every step."
  • What matters"Which single line matters most here? What would happen if I deleted it? Let me guess first."
  • Find the bug"Put one small bug in this code and let me find it."
  • Tiny numbers"Run this idea on a dataset of 4 rows so I can check every number by hand."
The explain-back testClose the chat. Write two sentences about what your cell does. Then paste them back and ask, "What did I get wrong or leave out?" If you can explain it without the chat open, you understand it.
